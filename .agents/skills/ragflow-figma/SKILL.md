# RAGFlow в Figma

Прочитай [руководство проекта](../../../docs/develop/figma-workflow-ru.md).
Оно определяет структуру, источники токенов, границы изменений, шаблон задания
и критерии готовности. Не дублируй его в новых инструкциях.

## Начало задачи

- Используй файл и узлы из текущего запроса. Если их нет, проверь доступный
  контекст проекта; исторические ссылки из руководства требуют проверки доступа
  и содержимого. Не выбирай старый файл молча при нескольких подходящих целях.
- Различай перенос текущего интерфейса, новый вариант дизайна и реализацию
  макета в коде. Запиши сценарий, результат, разрешённые изменения и нужные
  состояния коротким брифом по шаблону руководства.
- Для переноса найди владельца экрана, его общие компоненты, локальные стили,
  локализацию и фактическое состояние интерфейса. Зафиксируй источник и дату.
  Снимок браузера показывает runtime; исходники — checkout. При различии
  обозначь его, не выдавай один источник за другой.

## Выполнение

Используй подключённый Figma-плагин и его актуальные инструкции. Для JavaScript
в файле загрузи `figma-use`; для составного экрана — также
`figma-generate-design`; для создания компонентов или токенов —
`figma-generate-library`; перед созданием нового файла — `figma-create-new-file`;
для реализации дизайна в коде — `figma-design-to-code` до `get_design_context`.
Это инструкции инструмента; проектное руководство их не заменяет.

Сначала проверь структуру целевого файла, библиотеки и существующие компоненты.
Размещай новые предложения отдельно от текущего состояния. Не отсоединяй
instances и не меняй общие компоненты ради локального варианта без необходимости
в рамках задачи. Предпочитай нативные редактируемые слои и Auto Layout.

При ошибке с возможным частичным изменением перечитай затронутый участок перед
повтором. При лимите интеграции или отсутствии доступа сохрани подготовленный
результат локально и перечисли неприменённые действия; не называй Figma готовой.
Не меняй тариф, публикацию библиотек или права доступа без запроса пользователя.

## Завершение

Пройди применимую часть критериев готовности из руководства. Проверь структуру
слоёв и изображение результата; снимок сам по себе не доказывает редактируемость.
Верни ссылки на узлы, выполненные проверки и конкретные оставшиеся пробелы.
Не переноси результат проверки старого макета на изменённый файл или новый код.

Изменения кода выполняй только в объёме запроса, по `AGENTS.md`,
`web/AGENTS.md` и `test/REGRESSION.md`. Работа с макетом сама по себе
не разрешает менять приложение, выполнять коммит или деплой.
