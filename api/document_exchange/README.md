# Общий обмен документами

Общая реализация чтения находится в `pages.py`: поиск по названию или ссылке,
точное сопоставление названия, разрешение ссылки и получение опубликованной
страницы. ТЗ и БТ используют эту реализацию. Контекст подключения передаётся
снаружи: он выбирает личный токен, проверяет область доступа, переводит ошибки
и закрывает клиент при успехе и сбое. Транспортный модуль не импортирует ORM,
инициализацию приложения или процесс БТ. Преобразование HTML передаётся отдельно;
проверка девяти разделов остаётся в ТЗ. Хеширование нормализованного Markdown
вынесено в `content.py`; `merge.py` выполняет консервативное объединение B/L/R.

Старые публичные методы чтения БТ делегируют общему модулю. Только необязательная
привязка БТ может сохранить `LINK_ONLY` при недоступной Eva; импорт ТЗ получает
ошибку, а не неподтверждённую связь. `operations.py` хранит журнал попыток импорта
и их результаты. Первым потребителем журнала является ТЗ. Публикация использует общий вызов `publish_draft` из `pages.py`.

## Журнал импорта

`DocumentExchangeOperation` хранит область организации, продукт, пользователя,
ID запроса, контекст проекта, хеш и параметры запроса, состояние, ID попытки,
аренду и результат. Результат содержит только ссылку на локальный документ;
при повторе возвращается его актуальная проекция с повторной проверкой доступа.
Если результат уже недоступен пользователю или удалён, завершённая операция
возвращает `document_unavailable=true` без ID и названия документа. Это позволяет
закрыть сохранённый запрос, но не создаёт документ повторно.
Учётные данные, текст документа и ответы модели в журнал не копируются.
Адреса с учётными данными отклоняются до записи; параметры запроса и фрагмент
ссылки удаляются. Идентификатор относится ко всей операции: его повтор с другим
проектом, страницей, версией или режимом копирования отклоняется.

| Состояние | Поведение |
| --- | --- |
| `processing` | Одна попытка владеет шестиминутной арендой; сетевое чтение выполняется вне транзакции |
| `completed` | Создание документа, редакции, связи и запись результата завершены одной транзакцией |
| `failed` | Документ не записан; тот же запрос можно повторить с новым ID попытки |
| `canceled` | Запоздавшая попытка не может создать документ; повтор отменённого запроса отклоняется |

После истечения аренды тот же запрос получает новую попытку. Прежний исполнитель
проверяет свой ID перед записью и не может завершить её после повтора или отмены.
Повтор незавершённого запроса с действующей арендой сообщает о выполнении, а не
запускает второй импорт. Сбой записи откатывает документ и результат вместе.
Потеря ответа после успешной транзакции восстанавливается чтением сохранённой
ссылки. Ошибка записи сообщения о сбое оставляет аренду для восстановления.

Отмена создаёт запись `canceled` даже до доставки исходного запроса. Если создание
уже завершилось, отмена возвращает созданный документ и сохраняет `completed`.
Блокировка записи операции определяет единственный итог гонки отмены и создания.
Этот протокол защищает локальный импорт, который только читает Eva. Для внешней
публикации дополнительно требуется атомарный контракт Eva и сверка её результата;
локальный журнал этих гарантий не добавляет.

## Общие привязки БТ и ТЗ

`identity.py` вычисляет одинаковый ключ страницы для строкового адреса Eva,
списка и кортежа origin. Идентичность включает origin, пространство и ID страницы;
разные ссылки на одну страницу не обходят ограничение. Личный токен не входит
в идентичность.

`DocumentExchangeBinding` хранит владельца активной связи: организацию, тип
документа, ID и ключи страницы. Для личного проекта ТЗ областью является владелец.
Уникальные индексы запрещают вторую активную связь внутри этой области независимо
от типа документа. Сохранённое глобальное ограничение связей между БТ остаётся
частью контракта БТ. Таблицы продуктов хранят содержимое и версии связи;
общий реестр отвечает за её занятость.

`bindings.py` работает на транзакции вызывающего адаптера. Создание документа,
занятие страницы и запись редакции сохраняются или откатываются вместе. Смена
страницы заменяет резервирование в той же транзакции; конфликт сохраняет старую
связь. Удаление БТ освобождает его страницу. Чтение занятости выполняется пакетно.
Права и раскрытие ссылки на документ остаются в продукте: ТЗ открывает доступное
ТЗ, для недоступного документа или БТ предлагает независимую копию без связи;
БТ не раскрывает идентификатор и название занявшего страницу ТЗ.

`migrations.py` переносит существующие активные связи после их обычного
восстановления из событий БТ. Перенос повторяем и выполняется одной транзакцией.
При двух сохранённых владельцах одной страницы обновление останавливается,
данные не переписываются и победитель автоматически не выбирается. Сначала
нужно устранить конфликт в исходных связях. Содержимое документов, история,
комментарии и личные черновики при переносе не изменяются.

## Публикация в MVP

По уточнению пользователя обмен обновляет ту же страницу обычным API Eva,
как существующий сценарий БТ. Серверных расширений Eva и собственной таблицы
квитанций в Eva нет. ТЗ использует `EvaPages.publish_connected_page`, а БТ —
общий `publish_draft` для публикации подготовленного черновика и проверки результата.
Права, согласование БТ и локальная история остаются у соответствующего продукта;
для ТЗ цикл согласования не добавляется.

Перед записью ТЗ проверяются страница, проект, полученная версия, опубликованный
текст и чужой неопубликованный черновик. Затем сохраняется и перечитывается
черновик, выполняется штатная публикация и проверяются текст и название результата.
Обновление идёт по ID существующей страницы, новая страница не создаётся.
Записи выполняются личным токеном без автоматических сетевых повторов.
Клиенты чтения и записи общего сценария закрываются при успехе и ошибке.

ТЗ сохраняет текущую попытку и номер выгружаемой редакции в собственной проекции.
Параллельный запуск отклоняется; локальное редактирование может продолжаться,
успешная выгрузка не перезаписывает более свежий локальный текст. При ручном
повторе сначала читается Eva: совпавшие текст и название не публикуются повторно.
При неподтверждённом результате интерфейс предлагает проверить страницу Eva.

Проверки до и после вызовов не являются атомарной условной записью на сервере
Eva. Между вызовами остаётся окно для внешнего редактора. MVP использует
существующий протокол БТ и не обещает серверную транзакцию или доказательство
исторического результата по квитанции. Обнаруженное расхождение сообщается
пользователю, автоматическое повторение записи не запускается.
