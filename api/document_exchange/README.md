# Общий обмен документами

Общая реализация чтения находится в `pages.py`: поиск по названию или ссылке,
точное сопоставление названия, разрешение ссылки и получение опубликованной
страницы. ТЗ и БТ используют эту реализацию. Контекст подключения передаётся
снаружи: он выбирает личный токен, проверяет область доступа, переводит ошибки
и закрывает клиент при успехе и сбое. Транспортный модуль не импортирует ORM,
инициализацию приложения или процесс БТ. Преобразование HTML передаётся отдельно;
проверка девяти разделов остаётся в ТЗ. Хеширование нормализованного Markdown
вынесено в `content.py`; `merge.py` выполняет консервативное объединение B/L/R.

Старые публичные методы чтения БТ делегируют общему модулю. Только необязательная
привязка БТ может сохранить `LINK_ONLY` при недоступной Eva; импорт ТЗ получает
ошибку, а не неподтверждённую связь. Публикация, журнал операций и общий реестр
связей между продуктами ещё не реализованы этим модулем.

## Проверенный контракт Eva

Проверка 20 октября 2026 года выполнена на локальной Eva
`public-v02.32.01.6007-release-official`, в отдельном QA-проекте. Использовались
только новые синтетические страницы; очистка проверена. Встроенное описание
методов доступно авторизованному пользователю по `/api/`.

- `CmfDocument.create` принимает заранее заданный `id` вида `CmfDocument:<uuid>`.
  Его нужно сохранять до вызова; после неизвестного результата сначала читать
  этот ID, а не создавать новую страницу. Это механизм сверки, а не разрешение
  автоматически повторять любой POST.
- `cmf_version` — токен записи; это не отображаемый номер выпуска `doc_version`.
- `CmfDocument.upsert` с фильтром по `id`, `project_id`, `cmf_version` и явно
  заданным `id` в изменяемых полях защищает запись черновика. Проверены успешная
  запись, отклонение устаревшей версии без изменения текста и два одновременных
  запроса: успешен ровно один. Отклонённая запись не создаёт вторую страницу.
- Обычный `CmfDocument.update` с условием версии не показал такой защиты:
  устаревшая запись прошла, оба параллельных запроса прошли. Предварительное
  чтение и последующая проверка результата не заменяют атомарную защиту.
- `CmfDocument.do_publish` — отдельный вызов. Успешная защита записи черновика
  не доказывает защиту публикации: между вызовами черновик могут изменить.
  На QA-странице проверены два варианта с устаревшим `cmf_version`: фильтр
  по версии вместе с аргументом ID и версия в параметрах метода. Оба вызова
  прошли и опубликовали изменённый черновик; эти варианты защиты непригодны.
  Проверка выполняется с `notify_persons=false`, синтетическая страница удаляется.
  Прямую запись в `text` сервер запрещает и предлагает `text_draft` + `do_publish`.
  Контракт условной публикации пока не подтверждён.

Воспроизводимая проверка контракта:
`test/integration/test_eva_write_contract_live.py`. Она запускается только с
`RAGFLOW_LOCAL_DOCKER_CONNECTOR_TEST=1` внутри существующего локального
контейнера приложения. Учётные данные читаются в память из QA-подключения,
повторы записи на уровне HTTP отключены. Это проверка API Eva, а не приёмка
журнала операций, публикации продукта или всех версий Eva.
