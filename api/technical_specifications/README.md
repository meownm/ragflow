# MVP технических заданий

Рабочее пространство для ТЗ из девяти разделов. Согласования нет: чат готовит
предложение, одно действие применяет проверенный результат. Комментарий не
изменяет документ. Редакция документа отличается от версии его проекции и от
версии страницы Eva.

## Архитектура

React → HTTP → `Specifications` → хранилище и модель через переданные зависимости.
Домен содержит только значения и правила формата. Вызовы Peewee, настройки модели
и HTTP живут в адаптерах. `runtime.py` собирает зависимости. API и дальнейшие
фоновые потребители должны вызывать ту же прикладную реализацию.

Модуль — локальное расширение. В upstream необходимы только регистрация моделей,
маршрут SPA и пункт навигации. Таблицы автоматически создаются существующим
инициализатором. Существующий процесс БТ не изменяется.

Права наследуются от существующего рабочего пространства источников. Владелец
и редактор изменяют ТЗ; участники с правом чтения просматривают его и хранят свои
личные черновики. Все серверные операции повторяют проверку доступа; знание ID
документа не даёт доступ к другому проекту или организации.

## Данные

- `TechnicalSpecification`: проект, заголовок, версия проекции, номер редакции,
  девять разделов, история сообщений, комментарии, предложения и связь Eva.
- `TechnicalSpecificationRevision`: неизменяемый снимок разделов, номер,
  автор, причина и время. Восстановление создаёт новую редакцию.
- `TechnicalSpecificationDraft`: отдельный черновик пользователя в документе,
  собственная версия, текст, область, исходная редакция, цитата и окружение.
- Уникальный ключ происхождения ограничивает активную привязку страницы
  пределами организации. Для личного проекта без организации областью является
  его владелец. Независимая копия сохраняет происхождение и не получает активную
  связь. Если связанное ТЗ находится в другом доступном проекте, открывается оно;
  если доступа нет, идентификатор и содержимое не раскрываются.

Содержимое ограничено 100 000 символов. Проекция с историей — 2 МБ. Предложения
чата хранят только изменённые разделы относительно неизменяемой исходной редакции;
API восстанавливает полный результат одним пакетным чтением этих редакций.
Сохранённые полные предложения читаются и при следующей записи переводятся в это
представление без изменения текста. История и контекст не обрезаются молча.
Каждый принятый запрос резервирует 800 КБ под полный допустимый ответ и правку
с учётом JSON-экранирования. При нехватке места запрос отклоняется до запуска модели.
Параллельные записи учитывают резерв; уменьшение уже переполненной старой проекции
разрешено. Долгое обсуждение может потребовать отдельного хранения сообщений.

## Алгоритмы

Сохранение выполняется в транзакции: проверка прав → сравнение версии → запись
проекции через CAS → добавление редакции при изменении текста. Модель и Eva
не вызываются внутри транзакции. Параллельное изменение отклоняет запись.

Чат получает полный текст ТЗ, историю и точный контекст сообщения. Предыдущие
предложения передаются модели как изменённые разделы и замечания без повторных
копий незатронутого текста. Ответ модели
должен быть завершённым JSON. Правки за пределами выбранной области отклоняются.
Сообщение с полным контекстом сохраняется до вызова модели. Состояния запроса:
`processing`, `completed`, `failed`; ID попытки защищает результат от устаревшего
исполнителя. Повтор выполняющегося запроса возвращает его состояние. После сбоя
можно повторить сохранённое сообщение; прерванный перезапуском запрос доступен для
повтора после истечения шестиминутной аренды. Это восстановление по действию
пользователя, без отдельной фоновой очереди. Комментарии не отменяют результат
генерации. Ответ к прежней редакции сохраняется, но его предложение неприменимо.
Ошибка записи результата переводит исходное сообщение в `failed`, если хранилище
доступно. Повтор сохраняет ID сообщения; завершённый ответ не дублируется. При
полной недоступности хранилища действует та же аренда восстановления после сбоя.

Предложение хранит исходную редакцию. Применение проверяет всё результирующее ТЗ
на противоречия, затем повторяет проверку версии при записи. Ошибка, отмена или
таймаут не сохраняют частичный ответ помощника. Качество смысловой проверки зависит от
модели и требует отдельной проверки на реальных примерах.

Цитата привязывается по полному совпадению с окружением. Сдвиг фрагмента допустим;
удаление или неоднозначное совпадение блокируют отправку. Переход на весь раздел
выполняется только явным действием. Локальная копия полного черновика сохраняется
сразу, серверная — с задержкой; конфликт черновиков не заменяет локальный текст.
При конфликте интерфейс показывает серверный вариант и ждёт явного выбора.
Второй вариант сохраняется на устройстве целиком и доступен для восстановления.
Ошибка синхронизации останавливает очередь до повторного чтения серверной версии.
Если не удалось сохранить и локальную копию, интерфейс сообщает об этом явно.

Ручные правки заголовка и разделов сохраняются на устройстве вместе с исходной
редакцией. Обновление серверного снимка переносит независимые изменения разделов;
пересекающиеся изменения требуют явного выбора. При недоступном локальном
хранилище все переходы маршрутизатора, включая общую навигацию и «Назад»,
блокируются до сохранения ТЗ. Для чата достаточно подтверждения сохранения полного
текущего черновика на сервере либо локальной копии; подтверждение более старого текста
не освобождает новый черновик. Несохранённые комментарии также блокируют переход.
Восстановление локального хранилища позволяет сохранить копию при повторном переходе.
Выход через браузер вызывает стандартную защиту от потери изменений.

Черновики комментариев разделены по области и ветке ответа. Отправка очищает
только отправленный вариант, сохраняя текст, набранный во время запроса.
Повтор комментария или ответа с тем же ID не создаёт дубликата; смена текста,
контекста или ветки с уже использованным ID отклоняется.

Общее текстовое объединение находится в `api/document_exchange/merge.py` и не
знает о ТЗ, БТ или согласовании. Оно сравнивает B/L/R, переносит непересекающиеся
правки строк и сохраняет все варианты пересекающихся правок. Неоднозначное
удаление среди повторяющихся строк считается конфликтом. Полностью повторяющийся
текст проверяется до дорогостоящего сопоставления. Позиции блоков не
используются как их идентичность. Смысловая проверка связанных разделов относится
к продукту ТЗ, а не к транспорту Eva.

## HTTP

Префикс: `/api/v1/source-workspaces/{workspace}/technical-specifications`.

| Операция | Метод и путь |
| --- | --- |
| Список и создание | `GET/POST /` |
| Просмотр и сохранение | `GET/PUT /{id}` |
| Личный черновик | `GET/PUT /{id}/draft` |
| История и снимок | `GET /{id}/revisions[/{number}]` |
| Чат | `POST /{id}/chat` |
| Комментарии, ответы, решение | `POST /{id}/comments` |
| Применение | `POST /{id}/apply` |
| Восстановление | `POST /{id}/restore` |
| Импорт или независимая копия Eva | `POST /import-eva` |
| Поиск страницы Eva по названию или ссылке | `GET /eva-pages?query=...` |
| Получение изменений Eva | `POST /{id}/pull` |
| Выбор значений в объединении | `POST /{id}/resolve-eva` |

Изменения принимают текущую `version`. Черновик принимает собственную версию
и целиком объект `draft`: `message_id`, `text`, `context`. ID сохраняется до успешной
отправки и меняется вместе с текстом или контекстом. Повтор отправки возвращает
сохранённый ответ; прежний ID с другим содержимым отклоняется. Новый черновик
имеет ожидаемую версию 0. Ошибки содержат
машинный `error_code`; 409 обозначает конфликт версии, контекста или предложения.

## Приёмка

Обязательны сценарии: девять разделов и преобразование Markdown; чат без
автоматического применения; одна новая редакция после применения; запрет
устаревших предложений; независимые и пересекающиеся правки; проверка связанных
ограничений; отсутствие перезаписи при гонке; восстановление черновика с цитатой;
изолированные черновики пользователей; комментарии без изменения текста;
история и восстановление как новая редакция; права и отзыв членства.

Поиск и чтение Eva используют `api/document_exchange/pages.py` с личным токеном.
Список выбора показывает ID, пространство, версию страницы и существующую связь
с ТЗ. Поисковая строка ограничена 500 символами, ссылка — 2000 символами,
выдача — 20 страницами. Занятость
проверяется одним пакетным запросом, права — по уникальным проектам результата.
Недоступный связанный документ не раскрывается. Изменение запроса сбрасывает
выбор и отменяет старый запрос; запоздавший ответ игнорируется. Перед импортом
сервер проверяет выбранные ID и версию. Существующее доступное ТЗ открывается
без перезаписи и повторного импорта его текста. Импорт
проверяет идентичность страницы и уникальность связи; повтор открывает документ.
Получение изменений сохраняет предложение, а не перезаписывает локальное ТЗ.
Выбор конфликтных значений подготавливает полный результат с сохранением
независимых правок; применение проверяет связанные ограничения, выбранную сторону
и повторно читает внешнюю версию до и после проверки моделью. После применения
базой становится R. Найденное противоречие переводит предложение в состояние
выбора и сохраняет конкретные замечания для интерфейса и следующего запроса чата.

История показывает различия выбранной и текущей редакций: название, добавленный
и удалённый текст. Полный снимок выбранной редакции доступен отдельно.
Запоздавший ответ не подменяет выбор; восстановление использует показанную
редакцию и текущую версию ТЗ и создаёт новую редакцию.

Полная готовность MVP дополнительно требует общей реализации публикации для
потребителей, общей уникальности связей с учётом БТ, журнала операций,
восстановления после неизвестного результата публикации, браузерной проверки
и приёмки на реальной модели. Создание страницы с заданным ID и условная запись
черновика подтверждены на локальной Eva; см. `api/document_exchange/README.md`.
Защита условной публикации пока не подтверждена. Эти пункты остаются частью задачи.
