# Технические задания как продукт

## 1. Назначение и цель

Автор ведёт ТЗ в исходном формате из девяти разделов, обсуждает его с помощником,
оставляет комментарии и обновляет ту же страницу Eva. Согласования ТЗ нет.
Помощник предлагает изменения; одно действие «Применить изменения» проверяет
результат и сохраняет новую редакцию. Комментарии и ответы помощника сами по себе
не изменяют текст ТЗ.

Этот контракт относится к модулю технических заданий, его HTTP и интерфейсу,
а также к используемому им общему обмену Eva. Жизненный цикл БТ остаётся в модуле
БТ. Согласованное БТ может быть основанием проверки соответствия, но не вводит
согласование ТЗ. Публикация приложения, коммит и деплой не являются действиями редактора.

Нормативные требования ниже имеют ID `TZ-01`–`TZ-40`. Их критерии и исполняемые
проверки перечислены в [матрице приёмки](../../test/fixtures/technical_specifications/requirements_traceability.md).
Описание реализации и команды остаются в [README](README.md).

## 2. Общие сведения, термины, сокращения и ссылки

| Понятие | Значение |
| --- | --- |
| Проект | Рабочее пространство источников; определяет участников и доступ |
| `version` | Версия всей серверной проекции: обсуждение, предложения и состояние обмена |
| `revision` | Номер неизменяемой редакции названия и девяти разделов |
| `remote_version` | Версия страницы Eva; не заменяет локальные `version`/`revision` |
| B / L / R | Последний полученный текст Eva / текущее локальное ТЗ / новый текст Eva |
| Предложение | Полный кандидат относительно исходной редакции; до применения не является ТЗ |
| Личный черновик | Текст сообщения и полный контекст конкретного пользователя и документа |
| Ключ повтора | ID логического сообщения, комментария или операции, связанный с его содержимым |
| Приёмка модели | Проверка решений модели и происхождения фактических запросов |
| Проверка интерфейса | Сценарий в собранном SPA с управляемым синтетическим HTTP; не реальная Eva |

Ссылки: [общий обмен](../document_exchange/README.md),
[правила формата](../source_workbench/document_standards.py),
[корпус модели](../../test/evals/technical_specifications/README.md),
[проверка соответствия БТ](../../test/evals/technical_specifications/alignment/README.md),
[границы проверок репозитория](../../test/REGRESSION.md).

**DoR — готовность изменения к реализации.** Известны пользователь и проект,
исходная и ожидаемая редакции, разрешённая область, положительный сценарий,
отказ по правам, конфликт версии и восстановление после потерянного ответа.
Для обмена указаны существующая страница Eva, B/L/R, ожидаемая версия и ключ
повтора. Для LLM зафиксированы входы, независимый ожидаемый результат и допустимые
вызовы; эталонный ответ не передаётся модели. Для нового требования выбраны
проверки из матрицы, необходимые тестовые данные и безопасная граница записи.
Это техническая готовность задачи, а не согласование документа пользователями.

**DoD — готовность результата.** Все затронутые требования имеют исполняемые
положительные и отрицательные проверки; связанные unit/API/UI-наборы проходят
на текущих исходниках. Для изменений общего обмена проверяются потребители БТ
и ТЗ и гонки на отдельном PostgreSQL. Для изменений UI проверяется собранный SPA;
для изменения решений модели — полный замороженный корпус на реальной модели.
Пропуск, ошибка окружения, незавершённый ответ или неполное происхождение вывода
не считаются успехом. Проверяются сохранение независимых правок, отсутствие
посторонних изменений, закрытие клиентов и удаление тестовых данных. Отчёт
называет исходники, команды, результаты и границы доказательства. Реальную
публикацию Eva нельзя объявлять принятой по ответам синтетического API.

## 3. Компоненты подлежащие доработки с описанием изменений

Это требования к одному действующему пути: React → HTTP → `Specifications` →
переданные адаптеры хранилища, модели и Eva. Домен владеет форматом и ограничениями;
приложение — сценарием; хранилище — транзакцией и CAS. Общий обмен владеет
идентичностью страницы, занятостью, журналом импорта, текстовым B/L/R и публикацией.
Смысл связанных разделов остаётся в ТЗ. Сетевые вызовы и модель не исполняются
в транзакции. Потребители БТ используют тот же общий обмен со своим жизненным циклом.

## 4. Конфигурирование (настройки)

### 4.1. Конфигурации сервисов (дополнительные)

| Ограничение | Контракт |
| --- | --- |
| Текст девяти разделов | Суммарно не более 100 000 символов; Unicode считается символами Python, не байтами |
| Название | 1–255 символов, непустое после проверки пробелов |
| Сообщение/комментарий | До 10 000 символов |
| Ответ помощника | До 30 000 символов |
| Цитата и окружение | Цитата до 10 000; prefix/suffix до 64 символов каждый |
| Проекция | 2 000 000 байт JSON; принятый чат резервирует 800 000 байт под результат |
| Аренда чат/публикация | 360 секунд; истечение не доказывает отмену внешней записи |
| HTTP-действия | Импорт/публикация 300 секунд, остальные действия 330 секунд |
| Выдача Eva | Не более 20 страниц; поисковый текст до 500, ссылка до 2000 символов |

Модель берётся из настроек пользователя/организации через существующий адаптер.
Контекст, предел выхода и объявленные возможности проверяются до запроса.
Ограничения модели нельзя обходить обрезанием ТЗ. Изменение настроек модели,
состава корпуса или порогов требует новой квалификации соответствующей границы.

### 4.2. Права, ограничения и управление правами

| Действие | Владелец/редактор | Читатель | Посторонний/другой проект |
| --- | --- | --- | --- |
| Читать ТЗ, историю, Markdown | Да | Да | Нет |
| Свой личный черновик | Да | Да | Нет |
| Читать чужой личный черновик | Нет | Нет | Нет |
| Изменять ТЗ, чат, комментарии, применять/восстанавливать | Да | Нет | Нет |
| Искать/импортировать/привязывать/обновлять Eva | Да и личные права Eva | Нет | Нет |

ID документа не является правом. Список, история, снимок, receipt и черновик
проверяют тот же проект. Для изменения дополнительно проверяется право `edit`.
Активный системный администратор (`is_superuser`, активная учётная запись)
видит полный список проектов и получает чтение их ТЗ, истории и Markdown
независимо от организации и участия в проекте. Для такого просмотра возвращается
роль читателя. Существующая роль проекта сохраняется, если доступ к организации
действует. Статус администратора не даёт дополнительных прав записи, управления,
импорта или публикации Eva. Личный черновик всегда ограничен текущим автором.
Операция модели, начатая с доступом, не получает бессрочного разрешения на запись.

## 5. Прототипы интерфейсов и сценарии использования

Основной экран показывает оформленный непрерывный документ из девяти разделов,
оглавление (на узком экране — переход к разделу), название, номер редакции и
состояние автосохранения. Режимы «Документ» и «Чат» отдельные. Комментарии,
«Требует внимания», источники и Eva открываются по запросу; история предоставляет
широкое сравнение двух выбранных редакций и восстановление прежней как новой.
Источники используют действующие основания БТ и связь Eva, без демонстрационных
операций с архитектурой или OpenAPI. Создание допускает необязательную цель,
которая сохраняется в первом разделе обычным автосохранением.

До ручного изменения раздела его исходный Markdown/HTML сохраняется без
переписывания. Оформленное редактирование использует существующую политику HTML;
выделение привязано к точной исходной цитате, а не к похожему отображаемому тексту.
Автосохранение последовательно: ответ на предыдущий ввод не подтверждает новый
ввод и не создаёт ложного конфликта. После ошибки запись повторяется явно;
локальная копия и существующая защита переходов сохраняются. Конфликт с внешним
текстом требует выбора пользователя. Область чата не расширяется автоматически.
Ранний серверный снимок собственного сохранения обрабатывается как подтверждение
отправленного ввода, а не как правка другого автора. Потеря фокуса не сбрасывает
историю отмены редактора; после неё работают отмена и повтор ввода.

Различия HTML локального редактора и Markdown, возвращённого Eva, сами по себе
не создают предложение или конфликт. Подтверждённые хэши опубликованного текста
и его разделов отличают реальные удалённые изменения от смены представления;
независимые локальные правки сохраняются при получении и применении изменений Eva.

Предложение показывает правки у затронутых разделов и одну кнопку применения;
оно также доступно в чате. Убрать предложение означает скрыть его в текущем
рабочем сеансе, а не удалить серверный результат. Нет кнопок
«Отправить на согласование», «Согласовать» или второго подтверждения применения.

| Экран/область | Состояния и доступное действие |
| --- | --- |
| Список | Загрузка; пустой список → создать/импортировать; ошибка → повторить; читатель без создания |
| Документ | Сохранён; локальные изменения; сохраняется; ошибка; пересекающийся внешний текст → выбрать вариант |
| Чат | Пустой; личный черновик; processing → проверить запрос; failed → повторить сообщение; ответ; предложение; старая редакция без применения |
| Цитата | Актуальна; сдвинулась с тем же окружением; исчезла/неоднозначна → запрет отправки и явный выбор другой области |
| Комментарии | Пустые/активные/решённые; отдельный ввод корня и ответа; ошибка запроса с сохранённым вводом |
| Импорт Eva | Поиск; явный выбор; занято; уже связано → открыть; копия; выполняется; receipt после reload → продолжить/отменить; недоступный результат |
| Обмен Eva | Не связано → связать; доступно получение; нет изменений; ready/needs_resolution; страница изменилась; publishing/published/failed/неподтверждено |
| История | Метаданные; загрузка выбранного снимка; различия и полный текст; ошибка; восстановление выбранного снимка новой редакцией |
| Соответствие БТ | Выбор оснований; выполняется; результат; неполное доказательство; ошибка/повтор; история, не подменяющая актуальную проверку |

**SC-01 — вопрос и правка.** Given сохранённое ТЗ и выбранный контекст, When
пользователь задаёт вопрос, Then документ и редакция не меняются. Для просьбы
об изменении появляется предложение. Одно применение создаёт редакцию после
смысловой и повторной версионной проверки. При выходе за область нужно явно
выбрать «Всё ТЗ»; частичная правка не сохраняется.

**SC-02 — прерванный чат.** Given принятое сообщение с полным контекстом, When
ответ потерян или исполнитель прерван, Then сообщение остаётся в чате; повтор
того же ID проверяет состояние или восстанавливает истёкшую попытку. Новая
редакция делает старый failed-запрос неповторяемым: нужен новый вопрос. Новый
личный ввод не заменяется поздним ответом старого запроса.

**SC-03 — комментарий.** Given область/ветка и личный ввод, When комментарий
принят, а ответ сети потерян, Then повтор неизменённого запроса даёт один
комментарий. Если во время запроса введён новый текст, он остаётся после ответа
и получает новый ID. Решение ветки не меняет ТЗ.

**SC-04 — повторный импорт.** Given выбранная страница и сохранённый receipt,
When браузер перезагружен после создания ТЗ, Then продолжение открывает созданный
документ без второго создания. Отмена, победившая в транзакции, запрещает позднее
создание. «Открыть ТЗ» может использовать тот же endpoint импорта: критерием
является отсутствие повторного создания/перезаписи, а не отсутствие HTTP POST.

**SC-05 — объединение.** Given B с лимитом 20, L с лимитом 35 и размером 40 МБ,
R с лимитом 50 и отдельным журналом Eva, When выбран L, Then во всех связанных
разделах итоговый лимит 35, размер 40 МБ и журнал Eva сохранены. При выборе R
лимит 50, обе независимые правки также сохранены. Противоречие или изменение R
не создаёт редакцию и оставляет замечания/контекст для следующего действия.

**SC-06 — публикация.** Given сохранённая редакция и существующая связь Eva,
When выполняется обновление, Then меняется та же страница и фиксируется номер
отправленной редакции. Потерянный ответ не даёт сообщения об успехе и не вызывает
автоматическую повторную запись. Поздняя ручная правка остаётся локальной.

**SC-07 — доступ и история.** Given открытое ТЗ, When доступ отозван во время
модели или сети, Then завершение не записывает запрещённый результат. Доступный
читатель может скачать сохранённую редакцию и просмотреть историю, но не применить
предложение. Восстановление старой редакции не уничтожает более новые снимки.

## 6. Логика работы

**Ручное сохранение.** Валидировать название и формат → проверить право редактирования
и `version` → сравнить логическое состояние → записать изменение текста и новую
редакцию одной CAS-транзакцией. Без изменения состояния нет записи, в том числе
для предложений в полном/компактном формате хранения. Устаревшая `version`
возвращает конфликт с сохранением локального ввода. Модель и Eva здесь не вызываются.

**Применение предложения.** Проверить доступ, исходную редакцию и предложение →
выполнить смысловую проверку вне транзакции (для Eva также прочитать страницу
до и после модели) → повторно проверить права,
редакцию/предложение/внешнюю свежесть → CAS и новая редакция одной транзакцией →
показать сохранённый результат. Ошибка на любом шаге не допускает частичного
текста. Комментарий между проверкой и записью не отменяет допустимую текстовую
правку; параллельный текст или заменённое предложение отменяет.

**Черновик.** На каждый ввод сохранить полный снимок на устройстве, затем
синхронизировать с серверной версией. Подтверждение сравнивать с полным текущим
снимком, а не только с текстом. При CAS-конфликте остановить очередь, перечитать
сервер, сохранить обе копии и показать явный выбор. Очистить только отправленный
ID. Навигация не освобождает более новый ввод по старому подтверждению.

**Цитата.** Искать точное `prefix + quote + suffix` в исходном разделе. Единственное
совпадение задаёт актуальное смещение; ноль или несколько совпадений блокируют
отправку. Сервер повторяет эту проверку. Переход на раздел/всё ТЗ выполняется
только действием пользователя.

**Чат.** Проверить авторство ID, редакцию, контекст и запас проекции → сохранить
user-message `processing` с новым attempt → один вызов модели → проверить JSON,
`required_sections`, область, завершённость и размер → атомарно сохранить ответ
и предложение. Повтор processing без истечения аренды не запускает модель.
Запоздалая попытка не меняет итог новой. После ошибки хранения ответ не объявляется
сохранённым; после полной недоступности действует восстановление по аренде.

**Комментарии.** Сохранить личный ввод области/ветки → отправить стабильный ID,
текст и контекст → проверить автора, область и повтор → добавить комментарий/ответ
либо изменить resolved по CAS. Разделы и `revision` не меняются. Подтверждение
очищает только отправленный снимок: более новый ввод остаётся с новым ID.

**История.** Загрузить список редакций → открыть выбранный полный снимок → показать
отличия от текущего текста. При восстановлении проверить доступ и `version`,
записать выбранные название/разделы новой редакцией, если они отличаются.
Обсуждение, личные черновики и более новые исторические снимки сохраняются.

**Импорт.** Сохранить на устройстве operation_id и точный запрос → получить/занять
персональную операцию с fingerprint → проверить выбранную страницу и версию →
прочитать/разобрать Eva → атомарно создать документ, связь, редакцию и receipt.
Сверить attempt и отмену перед записью. Запрос состояния повторяет проверку
доступа к результату. Неизвестный или недоступный итог не порождает новое создание.

**B/L/R.** Сначала обычное трёхстороннее текстовое слияние. При конфликте показать
все стороны и предложить выбор фактов. Модель возвращает точечные замены цитат
готового снимка. Все замены проверяются до применения. Смысловая проверка видит
полные B/L/R, выбор и итог; сравнивает связанные факты и эквивалентные единицы.
Исправленное исходное противоречие не является ошибкой результата. После
успешного применения база обновляется до R, не до произвольного результата L.

**Внешняя запись.** Проверить идентичность, версию, опубликованный текст и чужой
черновик → сохранить и перечитать подготовленный черновик → штатно опубликовать →
сверить название и текст результата → сохранить локальную квитанцию попытки.
Обычный API Eva не предоставляет доказанного атомарного CAS; существующий чужой
черновик блокирует запись, а неопределённый итог требует проверки. Локальный
журнал не добавляет Eva отсутствующих гарантий конкурентной записи.

## 7. Модель данных

| Объект | Поля и инварианты |
| --- | --- |
| ТЗ | Проект/организация, id, title, version, revision, sections, messages, comments, proposals, eva, origin, eva_export |
| Редакция | document_id + number уникальны; title/sections/author/reason/time неизменяемы |
| Личный черновик | actor + document уникальны; отдельная version; полный объект draft |
| Контекст | document_id, revision, scope=`all`/`1`…`9`/`selection`, anchor=null либо section/quote/prefix/suffix |
| Сообщение | id, author, role, text, context/source_revision, status, attempt, started_at, error; assistant связан с user-message |
| Комментарий | id, author, text, context, resolved, replies; ID ответа связан с веткой |
| Предложение | id, source, base_revision, status, candidate, issues; для Eva также B/R/binding/resolution/conflicts |
| Связь Eva | origin + project_id + document_id, remote_version, page_url, base; личный токен не является идентичностью |
| Операция импорта | actor/workspace/operation_id, fingerprint, state, attempt/lease, result; canceled-транзакция запрещает позднее создание |
| Попытка публикации | id, status, отправленная revision, started_at/published_at; поздний локальный текст не подменяет отправленный снимок |

Проекция и редакция записываются одной транзакцией. Предложения чата могут
храниться как изменения относительно неизменяемой редакции; API возвращает
полные разделы. Это представление не изменяет смысл и не позволяет потерять
незатронутый текст. Личные черновики не входят в общую проекцию другого пользователя.

## 8. Сигнатура взаимодействия

Префикс `/api/v1/source-workspaces/{workspace}/technical-specifications`.
Для каждого endpoint обязателен существующий механизм аутентификации API;
затем выполняется сценарная проверка доступа. ID/строки проверяются до побочных
действий. Изменяющее тело — JSON-объект, не массив или строка.

| Метод и путь | Обязательные данные / результат |
| --- | --- |
| GET /; POST / | Список; создание `{title}` → проекция с revision=1 |
| GET /{id}; PUT /{id} | Проекция; `{version,title,sections}` → сохранённая проекция |
| GET/PUT /{id}/draft | Свой черновик; `{version,draft}` целиком; первоначальная version=0 |
| GET /{id}/revisions[/{number}] | Метаданные либо конкретный неизменяемый снимок |
| POST /{id}/chat | `{version,draft:{message_id,text,context}}` → актуальная проекция |
| POST /{id}/comments | `{version,message_id,text,context}`; ответ: `action=reply,comment_id`; решение: `action=resolve,comment_id,resolved` |
| POST /{id}/apply | `{version,proposal_id}` → проверенная проекция, одна редакция |
| POST /{id}/restore | `{version,revision}` → новая редакция при изменении текста/названия |
| POST /{id}/export | `{revision}` → `{filename,mime_type,content,revision}`; не требует версии обсуждения |
| GET /eva-pages?query=... | items с id/project_id/version/web_url/занятостью; доступное связанное ТЗ отдельно |
| POST /import-eva | `{url,copy?,operation_id?,selection?:{id,project_id,version}}` → существующее/созданное ТЗ |
| GET /import-eva/{operation_id} | Персональная квитанция и доступный результат |
| POST /import-eva/cancel | Тот же operation_id и fingerprint запроса → canceled либо completed |
| POST /{id}/connect-eva | `{version,url}` → связь без замены текста |
| POST /{id}/publish-eva | `{version}` → подтверждённое состояние той же страницы |
| POST /{id}/pull | `{version}` → предложение либо неизменённая проекция |
| POST /{id}/resolve-eva | `{version,proposal_id,choice:local|remote}` → готовое предложение |

Контракт проверки соответствия БТ, её каталог/история/бюджеты и доказательства
описаны в [профильном наборе](../../test/evals/technical_specifications/alignment/README.md).
Текущий редактор передаёт ему сохранённую revision, выбранные основания и
стабильный ID запроса; локальный dirty-текст блокирует запуск.

Ожидаемая ошибка сценария имеет `code/message`, а в `data.error_code` — машинный
код сценария. Ошибка аутентификации использует общую обёртку приложения:
HTTP 401, `code=401`, `message`, `data=null`, без обязательного `error_code`.
Общий ответ на нераспознанный сбой хранения/сервера: HTTP 500,
`code=100`, `message="Internal server error"`, `data.error_id/request_id` и
заголовок `X-Error-ID`; внутренние детали исключения не выдаются клиенту.
Это не подтверждение сохранения: интерфейс сохраняет ввод, а состояние принятого
сообщения проверяется отдельно. Доменный `error_code` не подменяет ID диагностики.
Основные группы: 401 — аутентификация; 403 — доступ; 404 — объект/действие;
409 — `VERSION_CONFLICT`, `STALE_MESSAGE`, `STALE_PROPOSAL`,
`IDEMPOTENCY_KEY_REUSED`, `EVA_CHANGED`, `EVA_NOT_BOUND`, `EVA_ALREADY_BOUND`,
`EVA_BINDING_EXISTS`, занятая попытка; 422 — структура/формат/размер;
502/таймаут — неподтверждённая модель или внешняя операция. UI показывает причину
и сохраняет локальный ввод; успешная HTTP-обёртка не заменяет проверку доменного
статуса. Неизвестное действие не вызывает произвольный метод сервиса.

## 9. Журналирование

История редакций хранит автора, причину и время изменения текста. Сообщения и
журнал операций хранят ID логического запроса, ID попытки, состояние и безопасный
код ошибки. Идентификаторы помогают связать запрос, ответ, предложение и редакцию.
Токены Eva, заголовки авторизации и приватные тела не включаются в технические
диагностические метаданные. Разбор синтетического тела для приёмки выполняется
внутри прокси; наружу возвращаются только проверяемые параметры и метаданные.

Приёмка состоит из отдельных результатов: домен/приложение/HTTP, хранилище и
гонки PostgreSQL, компоненты React, собранный браузер, модель, реальная внешняя
операция. Для каждого результата фиксируются точные исходники/хеши, команда,
полный набор выбранных случаев, итог и очистка. Синтетический API не доказывает
доступность Eva, unit fake не доказывает решение LLM, а успешная модель не
доказывает права, транзакции и браузер. Частичный прогон/отбор случаев — диагностика.
Обрыв upstream до заголовков не классифицируется в отчёте как смысловая ошибка.

Матрица приёмки содержит Given/When/Then, положительные/отрицательные варианты,
уровень проверки и точные тесты. Текущее выполнение хранится отдельно от требований:
изменение описания или списка тестов само по себе не превращает результат в PASS.
