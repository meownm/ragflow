## Исправления, проверенные во время репетиции

Помимо [исправлений предыдущего прохода](bt-demo-rehearsal-fixes-20261021.md):

- `ALL_SECTIONS_EMPTY` отнесён к фактам текущего AST. Он не переносится из старого
  анализа после заполнения; действительно пустые разделы сохраняют актуальные
  `REQUIRED_SECTION_EMPTY`.
- Проекция протокола больше не возвращает структурные предупреждения из
  неизменяемых событий. Сами события и примечания об источниках сохранены.
  Проверены и JSON API, и фактическое исчезновение панели в интерфейсе.
- Анализатор, как и планировщик, явно получает `active_eva_update_event_ids`.
  Пустой список комментариев не отменяет сравнение активной загрузки EVA.
  Контекст не усечён, дополнительных модельных проходов не добавлено.
- Версия виртуального проекта в `uv.lock` приведена к 1.51.3; форматирование
  Python проверено. Форматирование двух runtime-файлов сохранило их Python AST.

Это локальное расширение Business Documents. Владельцы: API AI adapter,
промпты БТ, domain content, completion/application и чистая проекция queries.
ACL, транзакции, идемпотентность и lease-проверки не менялись. Проверены прямые
потребители: worker, HTTP projection, существующий UI, EVA и экспорты.

## EVA и экспорты

Для собственных учебных данных использованы доступ выделенной QA-учётной записи
и новая страница `DOC-E8F76179`; секреты не записывались в сценарий или доказательства.

Первый анализ импорта вернул пустые вопросы/предложения, хотя полный внешний
текст содержал новое правило главной страницы. Результат сохранён в архиве и не
зачтён как успех. После явной передачи активных EVA ID опубликована новая внешняя
редакция того же правила с другим порядком слов и выполнена повторная загрузка.
Дополнительный обходной комментарий в БТ не добавлялся.

Повторный анализ создал предложение. Его формулировка «заменить первый абзац»
была слишком широкой, поэтому результат отдельно сверен с прежними требованиями.
Фактическое применение добавило фразу и сохранило остальное: **ревизия 4,
изменился только раздел 1; остальные 14 разделов идентичны ревизии 3**.
Все 19 проверок содержания и состояния в `document-checks.json` прошли.
Открытых вопросов, `PENDING` и предупреждений нет; итог `AGREED`.

«Сохранить текущий вариант в EVA» → просмотр варианта и различий → подтверждение →

## Оставшееся препятствие перед записью

**Раздел 4.1 содержит некорректную концептуальную схему PlantUML.** В AST пять
схем, в опубликованной странице четыре SVG и один сохранённый блок исходника.
Локальный реальный компилятор возвращает для этой схемы HTTP 400,
`Syntax Error? (Assumed diagram type: component)`, строка 8; исправная контрольная
activity-схема возвращает HTTP 200. Исходник смешивает `component` и последовательный
сценарий с `alt/else`. Смысловой `PASS` и `PUBLISHED` не доказывают валидность всех схем.

Повторный вызов конвертера EVA также не построил SVG и показал серверный
`AttributeError: 'str' object has no attribute 'decode'`; это отдельная ошибка
диагностики EVA. Исходный PlantUML сохранён, данные не потеряны.
Перед записью нужно исправить эту схему и подтвердить пять корректных SVG.
Эта генерация не является беспроблемным готовым примером для съёмки.
