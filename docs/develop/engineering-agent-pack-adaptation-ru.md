## Использование

Обычный запрос может подобрать skill по описанию; явные примеры:

> Используй $ragflow-authorization-matrix: проверь доступ к истории результатов
> SQL Assistant для владельца и пользователя другого tenant. Только ревью.

> Используй $ragflow-refactor-slice: вынеси расчёт из текущего владеющего модуля,
> сохрани ошибки, порядок и отмену. Изменяй только согласованный срез.

Эти примеры не запускают проверки или работу при чтении документа. Новые
проектные skills обнаруживаются Codex автоматически; если они не появились,
перезапусти Codex по инструкции OpenAI Docs. Обычное ревью использует текущие
правила; отдельного `adversarial-review` или `/goal` для него не требуется.

или рефакторинг на этих инструкциях не проверены. Валидатор проверяет структуру,

следующей инженерной задачи. Приложение, модели и runtime RAGFlow не изменялись;
product regression, независимое ревью и commit/push/deploy не запрошены.

Следующее полезное наблюдение — применение skill в подходящей реальной задаче
с фиксацией принятого результата в её существующем отчёте. Это не оставшийся
этап установки и не новый реестр.

Строка существующего пилота: scope — адаптация инженерных инструкций, риск
низкий; один основной агент, без делегирования. Время до результата и чистое
время интеграции неизвестны; наблюдаемое вмешательство пользователя — один

Model usage/cost и cached usage неизвестны. Приёмка ограничена проверками
выше; данных о последующих регрессиях или откате пока нет.

## Уточнение: компактность кода

По запросу пользователя «проверка, что код написан компактно» существующий
пункт Simplicity в AGENTS.md уточнён до Compactness and simplicity,
а в профиле code_reviewer добавлена обязательная явная оценка компактности.
Проверяются повторы, ветвления, вложенность, промежуточное состояние,
необоснованные слои, повторные обходы/I/O и лишняя универсальность.
Замечание требует конкретного более простого решения с сохранением контракта;
число строк не является самостоятельной целью. В результате ревью должна
появляться короткая строка «Компактность: …» с областью и пробелами проверки.

Потребители — основной агент и существующий code_reviewer; новых skills,
агентов и числовых порогов не добавлено. Изменение касается инструкций,
оценка конкретного прикладного кода в этом уточнении не выполнялась.
Приёмка: явный пункт ревью, конкретные основания для упрощения, защита
поведения и читаемости, сохранение review-only. Проверки текста, ссылок
и конечного diff выполнены владельцем изменения: `git diff --check` для
двух tracked-файлов — PASS; UTF-8, trailing whitespace и 30 локальных ссылок
в пяти файлах — PASS, включая новую ссылку на раздел компактности.
Самопроверка текста различает полезное упрощение и сокращение с потерей
контракта; это не испытание роли на реальном коде. Независимый запуск роли
на этих инструкциях не выполнялся.
