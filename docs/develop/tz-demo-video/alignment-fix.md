# Исправление отчёта и границы доказательств

`ALIGNMENT_REPORT_INVALID` возникал, когда согласованное БТ содержало полные
шаблонные отметки отсутствия требований. Обычное `IMPLEMENTED` требует настоящей
ссылки на ТЗ; выдумывать такую ссылку или удалять фрагмент из inventory нельзя.

Теперь `NO_REQUIREMENT` принимается только для двух точных полных маркеров:
«Требования не определены.» и «Параметры производительности и доступности не
определены.». Маркер допускается отдельным полным абзацем либо после точного
канонического заголовка опубликованного шаблона. Смешанный текст, нормативный
суффикс, неизвестный заголовок и кодовый блок этим исключением не покрываются.
Все строки остаются в полном отчёте и совместной проверке. Маркер нельзя
выдавать за реализованное требование; полностью пустой нормативный набор не
квалифицируется. Проверки цитат, редакций, прав и актуальности сохранены.

Для native Ollama 0.32.14 добавлен узкий протокол доказательства входа. Он
проверяет дословное наличие исходного сериализованного запроса в эффективном
prefill, совпадение render hash в двух окнах, точный серверный счётчик из
типизированного отказа малого окна и digest с восстановленным контекстом.
Сырые рассуждения остаются в памяти и не архивируются. Неподдерживаемая версия,
дрейф, неполный ответ, неизвестный расход или таймаут дают INCOMPLETE. Общий
предел 300 секунд и удержание резерва при неизвестном расходе сохранены.

V2 ожидает оба независимых запроса малого окна, сопоставляет полный render,
затем явно загружает исходное окно пустым chat-запросом. Принимается только
`done_reason=load` без генерации; после него обязательны фактический loaded
context и digest из `/api/ps`. Контракт пустого запроса проверен по
[исходнику Ollama 0.32.14](https://github.com/ollama/ollama/blob/v0.32.14/server/routes.go#L2445-L2463).
Неожиданный ответ загрузки оставляет неизвестный расход и INCOMPLETE.

Первый полный проход после исправления: согласованное БТ → ТЗ редакции 3 →
PASS / COMPLETE / VERIFIED / current=true / qualifies=true → публикация той же
страницы Eva → точное независимое чтение всех девяти разделов. В inventory
18 строк: 13 реализованных требований и 5 полных маркеров отсутствия требований.
На исходном контрольном ТЗ тот же проверяющий дал полный VERIFIED-отчёт с
отрицательной смысловой оценкой: требование повтора BR-03 найдено как MISSING.
Оба доказательства независимо сверены с actual wire существующего прокси;
дедупликации и подмены ответов не было.

Это приёмка основного пути. Она не заменяет FULL, NATURAL-BOUNDARY, отмену,
весь корпус, отдельные главы merge или матрицу прав. Исходные отказы остаются
в истории. Результаты съёмки и её точные ограничения фиксируются отдельно.
