# UI-kit рабочих разделов

Источник дизайна: [Figma, UI-kit и четыре раздела](https://www.figma.com/design/iMMjFhnmBxdLhBpPoW37uC/?node-id=5-2).
Контрольные макеты: страница `33:2`, БТ `33:183`, ТЗ `33:487`, SQL `33:749`, админка `33:977` (1280, Light), а также соответствующие 1440/Dark.

Пользователь выбрал перенос всего UI-kit и четырёх макетов в действующее приложение. Сохранены реальные данные, команды, история, права, автоматическое сохранение и подтверждения удаления. Фиктивный текст макетов в приложение не переносится. Исходные снимки Figma остаются историческим ориентиром.

Фондовые proposal-цвета перенесены в `--ui-*` в `web/tailwind.css`. Оболочка `.rf-workbench` подключает их для БТ, ТЗ, SQL и админки; остальные страницы не получают эту компоновку. Общие примитивы используют читаемые цвета и фокус также внутри порталов.

## Правила

- InterVariable/Inter; текст 14/20, подписи 12/16, заголовки разделов 18/28 и экранов 20/28.
- Рабочие отступы 24 px, промежутки 8/12/16/24 px. Левая колонка ТЗ и админки — 208 px на 1280 и 220 px на 1440. В БТ боковое содержание убрано: документ занимает всю область до обсуждения; обсуждение сохраняет ручную настройку ширины.
- Button: `xs=24`, `sm=28`, `default=32`, `lg=40`, `xl=48`. Содержимое центрируется flex без размерных элементов Figma. Focus — внешний контур 2 px с отступом 2 px.
- Обычная строка таблицы — фон документа; hover — нейтральная подложка. Selected — accent 10% и постоянный левый маркер 3 px, включая наведение. Выбор задаётся `data-state="selected"`, доступное состояние — `aria-selected` у потребителя.
- Акцентная кнопка имеет тёмную подпись в обеих темах. Статусы используют `--ui-success/warning/error`; смысл дополнительно выражается текстом и пиктограммой.
- Поля, таблицы и панели переносят длинный текст. Таблица с большим числом реальных столбцов прокручивается внутри своей области. Содержание документа и правая панель прокручиваются независимо.
- Редкие SQL-подробности открываются по запросу. Источник выбранного запуска остаётся возле его результата; подключение следующего запуска показывается отдельно.
- ТЗ показывает краткие предложения отдельно от сохранённого текста. Полное сравнение открывается для одного предложения; применение использует действующий контракт редакций.
- Нет доступа, ошибка загрузки, пустой список и отсутствие совпадений — разные состояния. Скрытие действий не заменяет серверную авторизацию.

## Соответствие компонентов

Доменным блокам не создаётся второй независимый набор состояния. Они используют существующих владельцев и общие примитивы.

| Figma | Реализация |
| --- | --- |
| Button / Internal/ButtonHeight | `components/ui/button.tsx`; высота задаётся размером CSS, внутренний Figma-элемент в DOM не нужен |
| Badge | `components/ui/badge.tsx`, включая `warning` |
| Input / Textarea / Select/Trigger | Одноимённые примитивы `components/ui`; высота поля 40 px задаётся потребителем через `h-10` |
| Checkbox / Switch | Одноимённые Radix-примитивы, controlled и uncontrolled состояния |
| Tab / MenuItem | `components/ui/tabs.tsx`, `dropdown-menu.tsx` |
| Table/Row | `components/ui/table.tsx` |
| Alert | `components/workbench/notice.tsx`; inline уведомления с текстом и пиктограммой |
| StatePanel | `components/workbench/state-panel.tsx`; загрузка, ошибка и пустые состояния |
| Status/Save | `BusinessDocumentStatus` и состояние сохранения владельца редактора ТЗ |
| Pagination / Field | `components/ui/ragflow-pagination.tsx`, `form.tsx`, `label.tsx` |
| Dialog / Drawer/Inspector | `components/ui/dialog.tsx`, `sheet.tsx`; действующие диалоги и панели разделов |
| Source/Link | `technical-specifications/alignment-panel.tsx`, блок Eva и существующий доступ к источникам БТ |
| Discussion/Item | `business-documents/components/question-item.tsx`, `proposal-item.tsx`, `technical-specifications/proposal-card.tsx` |
| Discussion/Composer | `business-documents/components/protocol-pane.tsx`, помощник и комментарии ТЗ |
| Revision/Row | История редакций БТ/ТЗ и `constructor/sql-revision-workspace.tsx` |
| SQL/Step / SQL/Entity / SQL/Result | `constructor/sql-agent-workbench.tsx`, `sql-schema-graph.tsx`; реальные этапы, сущности, результаты и срок хранения |
| Navigation/Item | Содержание ТЗ, реестр SQL и `admin/layouts/navigation-layout.tsx` |
| Shell/Header | `layouts/components/header.tsx` и оболочка админки, с сохранением действующей навигации |
| Document/Section | `business-documents/components/document-pane.tsx`, редактор разделов ТЗ |

В Storybook доступна витрина `RAGFlow/Workbench UI-kit` с Light/Dark: варианты и размеры Button, поля, статусы, диалог, таблица selected/hover и вкладки. Это реальные компоненты проекта; демонстрационные данные живут только в истории Storybook.

## Проверка и передача

Данные текущего запуска, исходный dirty-снимок, результаты проверок и сравнения хранятся в `.local/archives/ui-kit-transfer-20261028`. Базовый commit — `c008c0126a8aec778f5ff72c81347c6e6e507561`; до задачи уже были 17 изменённых SQL-файлов. Они сохранены в baseline-пакете и включаются в проверку развёртываемого снимка.

Версия 2.0.0 отражает перенос общей дизайн-системы и обновление четырёх рабочих разделов. API, форматы сохранённых документов и схема БД этим изменением не меняются. Полная release-квалификация и модельные прогоны не входят в UI-перенос.

Проверяемая граница: 1280/1440 × Light/Dark для UI-kit и четырёх разделов; отдельно переходы ТЗ, документ и изменение ширины обсуждения БТ, свёрнутые SQL-подробности и отказ в доступе админки. Полнота фактических проверок и ограничения фиксируются в отчёте запуска, а не предполагаются по наличию макета или проходу Jest.
