## Стартовое задание для Codex

Продолжи SQL-ассистент в существующем проекте ragflow по requirements-v0.5-ru.md. Начни с E0: обследуй фактическую реализацию OpenMetadata, RAGFlow retrieval, подключения к БД, SQL-конструктор, исполнение, права и состояние диалога. Не создавай второй каталог, новый frontend или параллельный executor без выявленной необходимости.

Зафиксируй в существующей задаче/PR:
- текущий commit и состояние локальных изменений;
- таблицу «требование/AC → существующий модуль → доказательство → пробел → следующий инкремент»;
- возможности и версии адаптеров, домен пилота, семантику метрик/JOIN/времени, доступы, ограничения и нерешённые вопросы;
- минимальный вертикальный инкремент E1 с наблюдаемыми исходами и проверками;
- зависимые решения, которые нельзя заменить предположением.

После обследования готовь реализацию последовательными инкрементами в рамках текущего задания пользователя; сам факт переноса документации не является распоряжением развернуть систему или выполнить SQL в промышленной БД. Не объявляй E0 закрытым при неизвестных обязательных решениях, не переноси готовность макета на готовность продукта. Сохраняй действующие функции и возможность обновления upstream. Локальные незакоммиченные изменения не перезаписывать.

## Порядок поставок

| Этап | Результат | Условие перехода |
| --- | --- | --- |
| E0 | Проверенный контур, домен, контракты, эталоны | G0: закрыты блокирующие решения и применимый DoR |
| E1 | Контролируемое исполнение и доказательства результата | G1: API-срез, права, лимиты, идемпотентность, отмена/UNKNOWN |
| E2 | Чат, уточнения, каталог, drill-down, сравнение | G2: ограниченный пилот и независимая проверка ответов |
| E3 | Конструктор, представление, @, сохранённые вопросы, SQL | G3: функциональная полнота P0 |
| E4 | Сквозная приёмка, эксплуатация, выпуск | G4: весь P0, DoD, владельцы, откат |
| E5 | Аномалии и ряды | G5: AC-05 и затронутый регресс P0 |
| E6 | Управление знаниями | G6: AC-11, согласование и безопасная публикация |

Точная матрица AC и зависимости — в требованиях. E5/E6 независимы после G4. Календарные даты и мощности команды не согласованы.

## Неприкосновенные правила расчёта

- OpenMetadata — каталог; RAGFlow — поисковый снимок; БД — фактические данные. Права на каталог не дают прав на строки.
- LLM предлагает намерение/объяснение. Согласованные расчёты строятся детерминированно из поддерживаемой спецификации.
- QuerySpec, QueryPlan, QueryRun, Result и ViewSpec имеют разные обязанности и версии.
- Скрытие/порядок/формат столбца и ряда меняют ViewSpec без SQL. Новое поле, метрика, JOIN, зерно, WHERE/HAVING меняют расчёт через черновик и новый запуск.
- UNKNOWN не разрешает автоматическую повторную отправку; поздний результат не заменяет активную ветку.
- Проверка определения, актуальность, полнота источника и полнота выдачи — независимые признаки.
- Ручной SQL не наследует подтверждённую семантику; неподдерживаемая грамматика не преобразуется конструктором с потерей смысла.
- Права повторно проверяются при поиске, перед моделью, исполнением и чтением результатов.

Макет содержит 65 демонстрационных экранов; исходная строка «восемь экранов» в снимке требований относится к раннему состоянию и не является текущей инвентаризацией. Figma — редактируемый прототип с заранее заданными переходами, без реального SQL и произвольного ввода.

Перед реализацией проверить известные ограничения прототипа:
- некоторые редакторы возвращают в фиксированный базовый пример вместо сохранения выбранного контекста;
- JOIN, выражения и ряд настроек показаны обзорными экранами вместо полноценных форм;
- @ и сохранение вопроса не демонстрируют реальный поиск/сохранение и все состояния;
- пример неподдерживаемого SQL не заменяет проверку реальной SQL-грамматики;
- подписи осей необходимо согласовать с ориентацией диаграммы и единицами;
- навигация примера LLM logs местами сохраняет подписи домена продаж.

При конфликте иллюстративного перехода с AC реализовать проверяемое требование и согласовать исправление макета. Демоданные и LLM logs не считаются выбранным промышленным доменом.
