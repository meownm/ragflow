# Конструктор результата

Персона: аналитик данных, конечный пользователь. База `5637343b4`, dirty checkout.
Изменяется локальное расширение SQL-помощника; общие UI-примитивы не меняются.
Один агент владеет реализацией и проверкой. Настройки Metabase служат образцом
сценария; реализация использует существующие представления RAGFlow.

Приёмка:
- Поля: видимость, порядок в обе стороны, название и формат; интерфейс не даёт
  скрыть последнее поле. Есть явные сохранение, отмена и сброс, ошибки сохраняют ввод.
- Фильтры: несколько условий И, операции сравнения/содержит/NULL, сортировка;
  сервер применяет их ко всему сохранённому набору, включая следующие страницы.
- Вид: таблица/график/оба, тип и оси графика, плотность, полосы и перенос текста.
  График явно ограничен текущей страницей, значения SQL не меняются.
- Метрики: карточка ячейки, число сохранённых строк и сводные показатели по
  детальным строкам после фильтра. NULL/пусто/нечисловое значение имеют отдельные
  состояния. Повторная агрегация SQL-агрегатов запрещена; новый расчёт открывается
  отдельно в существующем конструкторе SQL без автоматического выполнения.
- Настройки переживают перезагрузку. CAS, текущие права/tenant/каталог и retention
  сохраняются. Карточки значений не копируются в журнал и не переносятся на
  другой запуск; истёкшие и чужие данные не восстанавливаются.

Проверки: pure domain для метрик и настроек; SQLite/API для сохранения, конфликтов,
границ и прав; Jest для конструктора; type-check/ESLint/Ruff; собранная SPA и
Chromium в светлой 1440×1000 и тёмной 390×844 темах. Модель не нужна: новые
показатели вычисляются детерминированно. Полная runtime-приёмка и деплой отдельно.
