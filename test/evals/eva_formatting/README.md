# Регрессия форматирования Eva

Сценарий: автор сохраняет согласованное содержимое как черновик Eva,
публикует отдельным действием и загружает опубликованную страницу обратно.
Критерий: сохраняются текст, порядок, структура, оформление, URL, нумерация,
состояния checkbox, язык и пробелы кода. Второй цикл не должен добавлять потери.

Таблицы без заданной ширины получают штатную ширину Eva `100%` от контейнера,
включая вложенные таблицы. Заданные `width`, CSS-ширина таблицы и размеры ячеек
сохраняются. Корпус отдельно задаёт это ожидаемое представление `eva_html`;
компаратор по-прежнему считает потерю или изменение ширины ошибкой.
Браузерная приёмка проверяет реальную ширину и переносы текста, а для PlantUML —
открытие настроек экспортированного макроса, изменение UML, выпуск страницы
и обратный импорт точного изменённого исходника. Наличие SVG/параметров в API
само по себе не подтверждает редактируемость через плагин.

Это проверка **обмена без потерь**. Простое содержимое импортируется в Markdown;
таблицы и оформление вне Markdown сохраняются безопасным HTML. Backend и UI
используют одну политику `api/apps/business_documents/html_policy.json`:
разрешены оформление и checkbox только для чтения; запрещены исполняемые теги,
обработчики событий, опасные URL, внешние CSS-ресурсы и перекрывающие страницу
стили. В UI идентификаторы и локальные ссылки получают изолированный префикс
`business-document-<instance>-`, чтобы сохранять навигацию без DOM clobbering
и совпадения ID в соседних панелях. Якоря нумерованных заголовков сохраняются
служебным пустым anchor в теле Markdown и возвращаются в заголовок при рендере;
это сохраняет распознавание опубликованного шаблона и чистые названия разделов.
Нумерованные заголовки разделов следуют опубликованному шаблону.
Потери дают обычный `FAILED`, без `xfail` и ослабления ожиданий.

`cases.py` задаёт конечную матрицу: H1–H6/Setext, абзацы/переносы LF/CRLF/CR,
bold/italic/strike и вложения, Unicode/RTL/entities/NBSP, списки и нумерация,
checkbox, цитаты, таблицы/выравнивание/вложенность/объединения/пустые ячейки,
код/языки/ограждения/пробелы, ссылки/изображения, разделители, native HTML/CSS
Eva. Это классы оформления и их граничные примеры, а не все возможные
комбинации произвольного HTML/CSS. Исходные макросы PlantUML, их повторы,
некорректный SVG и недоступность рендера дополнительно покрывает существующий
`test/unit_test/api/apps/business_documents/test_eva_document_changes.py`.

## Запуск из корня репозитория

```powershell
.venv/Scripts/python.exe -B -m pytest -q test/evals/eva_formatting/test_roundtrip.py test/evals/eva_formatting/test_workflow.py test/evals/eva_formatting/test_html_boundary.py --tb=short -p no:cacheprovider --junitxml="$env:TEMP/eva-formatting.xml"
.venv/Scripts/python.exe -B -m pytest -q test/unit_test/api/apps/business_documents/test_eva_document_changes.py test/unit_test/data_source/test_eva_wiki_connector.py test/unit_test/api/apps/business_documents/test_business_document_eva_sync.py -p no:cacheprovider
```

Этапы: независимый ожидаемый HTML → экспорт; native HTML → импорт; два цикла;
реальные reader/writer и JSON-RPC с подменой только HTTP; согласование,
подготовка, публикация и `read_connected_page` с SQLite в памяти.
Для каждого варианта дополнительно проверяется реальный экспорт AST в Eva
и импорт обратно в AST. Проверяются координаты объединённых ячеек, вложенные
таблицы, некорректные размеры объединений и отсутствие HTML-тегов в текстовом
DOCX-экспорте; визуальная точность оформления DOCX не является этим сценарием.
Безопасный HTML проверяется отдельно от опасных тегов, URL и обработчиков.
Проверки прав, чужого пространства, токенов, версии, конфликтов и повторной
публикации находятся в соседних существующих unit-файлах из второй команды.
Индексирование Eva в RAG намеренно извлекает plain text и не является этим
сценарием редактирования.

В `web`:

```powershell
npm run test:focused -- --runInBand src/pages/business-documents/components/document-markdown.eva-formatting.test.tsx src/pages/business-documents/components/document-markdown.test.tsx
```

Это DOM-проверки компонента, не визуальная приёмка редактора Eva в браузере.
Сравнение backend HTML игнорирует только сериализацию таблиц, алиасы b/strong,
i/em, s/del, стандартные spans=1, обёртку таблицы без атрибутов и единственный
p **без атрибутов** внутри ячейки/пункта. CSS, структуру, пробелы кода,
URL и checkbox оно не исключает из проверки. Штатная обёртка таблицы
`wikitables` с классами `tableView-content-wrap cmf-scrollbar` и служебным
`data-id` считается представлением редактора; при импорте она удаляется,
а при экспорте создаётся заново без накопления лишних `div`. Обёртки с CSS,
якорем, направлением текста, заголовком или соседним содержимым сохраняют
значение в сравнении. Негативные примеры проверяют,
что сам компаратор обнаруживает потери. Дополнительно сравниваются реальные
представления редактора Eva: `tox-checklist`/`tox-checklist--checked` с
checkbox, последовательности номеров `ol reversed` с явными `li value`,
`font` с эквивалентным CSS. Префикс якорей `mcetoc_` снимается только со
ссылок с маркером Eva `cmf_converted` и их целей; percent encoding фрагмента
считается сериализацией. Отдельные негативные тесты запрещают считать
эквивалентными разное состояние checkbox, номера, размер шрифта и ID цели.

## Live: только локальный QA-контур

`test_live.py` запускается отдельно внутри application-контейнера с
`RAGFLOW_LOCAL_DOCKER_CONNECTOR_TEST=1`, на **копии текущего исходного кода**
с соответствующими зависимостями. Требует выделенную строку коннектора
`EVA Wiki native smoke` с локальным адресом и тестовым проектом. Токен читается
внутри процесса и не выводится. Пример после подготовки снимка:

```bash
RAG_PROJECT_BASE=/ragflow PYTHONPATH=/tmp/eva-formatting:/ragflow \
RAGFLOW_LOCAL_DOCKER_CONNECTOR_TEST=1 PYTHONDONTWRITEBYTECODE=1 \
/ragflow/.venv/bin/python -B -m pytest -q \
test/evals/eva_formatting/test_live.py --tb=short -p no:cacheprovider \
--junitxml=/tmp/eva-formatting-live.xml
```

Тест создаёт одну уникальную `regression-probe-formatting-*` страницу,
проверяет раздельное сохранение/публикацию, читает результат, затем удаляет
только её и проверяет отсутствие. Чужие страницы, настройки коннектора,
токены, runtime и deployment не меняются. Отсутствие opt-in даёт skip;
недоступность Eva, отказ в правах или ошибка очистки дают ошибку, а не pass.
Дополнительно проверяется полный цикл документа по опубликованному шаблону:
нумерованный заголовок с якорем → Eva → импорт в AST → повторный экспорт.
Нельзя трактовать offline/DOM результат как успешный live-прогон.

`-k plantuml_plugin` проверяет нативные плагины двух диаграмм: выгрузку поверх
того же текста в виде кода, сохранение SVG и редактируемых исходников, импорт
в AST и повторную выгрузку без новой публикации. Для изолированного runner
в Docker-сети можно задать `RAGFLOW_LOCAL_EVA_QA_API_URL=http://eva-wiki-http`;
это меняет маршрут только внутри теста, без сохранения настроек коннектора.

Перед записью применяется тот же `prepare_eva_html`, что в экспорте EVA_WIKI
и согласованном изменении: штатный checklist вместо удаляемого Eva input,
явные номера вместо удаляемого reversed, CSS вместо удаляемых font-атрибутов.
Reader остаётся транспортом исходного HTML; нормализация редактора выполняется
в адаптере Business Documents до импорта и проверки сохранённого черновика.
Повторы записи отключены: после оборванного ответа нельзя предполагать, что
удалённая операция не выполнилась. Ошибку транспорта следует сопоставлять с
журналами входного proxy и Eva, не принимать за ошибку форматирования.
